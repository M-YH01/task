# 1. 목표
과제 3 카드 도구의 JSON 복원 실패가 기존 작업을 훼손하지 않게 한다. **이 문서를 새 AI B에 전달하고 이전 대화는 전달하지 않는다.** 동일 최초 요청은 INITIAL_REQUEST.md, 고정 검사와 상한은 PROTOCOL.md 및 tests/cases.json. B도 최대 60분·도구 호출 80회이며 시작/종료·실제 사용량을 기록한다.

# 3. 실행 명령
Node.js 24와 전달받은 소스 폴더가 필요하다. 설치할 패키지는 없다. 압축 소스를 새 폴더에 풀고 그 폴더에서 아래 3단계를 실행한다. 1단계는 문서·코드·검사의 해시를 검증한 뒤 별도 폴더를 만들고 수신 영수증을 저장한다. 해당 폴더가 이미 있으면 다른 이름을 사용한다.
```sh
node tools/receive.cjs ../ai-b-work
cd ../ai-b-work
node tests/run.cjs evidence/b-initial-tests.json
```
현재 종료 코드 1과 8/10은 재현 성공이다. index.html을 브라우저로 열면 앱이 실행된다. B는 영수증에 기록된 HANDOFF 해시와 handoff-manifest.json의 기대값을 대조한다.

# 4. 통과 검사
T01–T08 통과. evidence/baseline.json, a-tests.json, fresh-folder.json 참조. A가 git archive로 새 폴더에 풀어 동일 코드 해시와 같은 8/10을 확인했다. 로컬 git clone은 Windows signal pipe 권한 오류로 실패하여 archive 방식으로 재현했다. tests/run.cjs는 실제 복원 함수를 실행하되 DOM·Image 이벤트를 대체한다. 실제 브라우저 검증은 아직 하지 않았다.

# 5. 남은 문제
T09: 이미지 onerror 시 이미 비율·문구가 바뀌고 이미지가 제거된다. T10: 이미지 onload 전 상태가 바뀌고 성공 알림이 뜬다. 둘 다 원래 있던 결함이다. 검사는 Image 이벤트를 수동 발생시키므로 네트워크 없이 재현된다. 브라우저의 실제 이미지 디코딩 및 연속 복원 경쟁 상태는 고정 10검사만으로 입증되지 않는다.

# 6. 다음 행동
B 시작 시각/도구 호출 수를 기록하고 위 8/10을 먼저 재현한다. index.html의 restoreFromProject에서 새 문구·비율·이미지를 임시 값으로 준비하고, 이미지가 없거나 로드가 성공한 뒤 한 번에 적용한다. 실패 시 상태를 바꾸지 않고 오류만 표시한다. 성공 알림은 적용 후 1회만 보낸다. 같은 검사로 10/10(종료 코드 0)을 확인하고 브라우저에서 정상/손상 JSON을 확인한다. B 종료 소스·사용량·수신 해시·무대화 재개 여부를 기록하고 비교 보고서의 B 미실행 칸을 실제 결과로 갱신한다. 사람의 판단 항목은 사용자에게 사실 확인한다.

# 7. 금지 범위
고정 10검사·기대값·최초 요청·상한을 바꾸지 않는다. 과제 4, 원본 폴더, 이미지 업로드/내보내기·템플릿 UI를 확대 변경하지 않는다. 무료 한도를 소진하지 않는다. 대화 전문·자격증명은 인수인계/공개 소스에 넣지 않는다. A 재현을 B 성공으로 쓰지 않는다. HANDOFF.md는 A 원본으로 보존하고 B 결과는 별도 문서에 쓴다.
